# VPL Baseline Notes

## 1. What This VPL Baseline Does

This VPL baseline is a pairwise-preference recommendation model. Instead of asking natural-language questions, it learns about a user by showing two products at a time and observing which product the user prefers.

Each feedback example has the form:

```text
(product A, product B, label)
```

where `label = 1` means the user prefers product A, and `label = 0` means the user prefers product B.

The goal is to infer the user's hidden preference vector and use it to rank candidate products.

## 2. Data Used by VPL

The model uses two main data sources.

First, it uses simulated users from the provided pickle splits:

```text
utils/user_train_set.pkl
utils/user_eval_set.pkl
utils/user_test_set.pkl
```

The split sizes are:

```text
train: 1000 users
eval: 125 users
test: 125 users
```

Second, it uses product embeddings:

```text
utils/product_embeddings.json
```

There are 187 products in the product pool. Each product is represented by an 8-dimensional embedding:

```text
comfort
functionality
maintenance
status_symbol
modesty
sustainability
risk_tolerance
trend_sensitivity
```

During evaluation, every test user is ranked against the full candidate pool of 187 products.

## 3. How Pairwise Preferences Are Generated

For each user, the simulator already has an 8-dimensional latent preference vector. A pairwise label is generated by comparing the utilities of two products for that user.

For a user latent vector `z_user` and a product embedding `x`, utility is computed as:

```text
utility(user, product) = 1 - mean((z_user - x)^2)
```

For a product pair `(A, B)`:

```text
if utility(user, A) >= utility(user, B):
    label = 1
else:
    label = 0
```

So the pairwise label is not manually assigned. It is generated from the user's latent preference and the two product embeddings.

## 4. Model Architecture

The model has two main components.

### Pairwise Belief Encoder

The encoder takes the observed pairwise preference history and maps it into a posterior distribution over the user's latent preference:

```text
q(z | preference history)
```

In the code, each pairwise observation is represented as:

```text
[product A embedding, product B embedding, label]
```

Since each product embedding has 8 dimensions, each pairwise feature has:

```text
8 + 8 + 1 = 17 dimensions
```

The encoder processes all observed comparisons, averages their hidden representations, and outputs:

```text
posterior mean: mu
posterior log-variance: logvar
```

This gives a Gaussian latent belief over the user's preferences.

### Latent-Conditioned Reward Model

The reward model takes:

```text
product embedding x
latent preference z
```

and outputs a score:

```text
r(x, z)
```

Products are ranked by this reward score.

## 5. Training Objective

Training follows the core idea of VPL: learn a latent preference model from pairwise comparisons.

The model is trained with a pairwise preference loss. For a query pair `(A, B)`, it predicts:

```text
logit = r(A, z) - r(B, z)
```

The binary label tells the model whether A or B should receive the higher score. This is a Bradley-Terry-style pairwise likelihood.

The training loss is:

```text
pairwise preference loss + beta * KL loss
```

The KL term regularizes the posterior distribution over the latent variable.

In the final baseline, latent alignment supervision is disabled:

```text
latent_alignment_weight = 0
```

This means the model is not directly trained to match the true latent vector. It must infer useful latent information through pairwise preference evidence.

## 6. Adaptive Pairwise Querying

At test time, VPL uses sequential active pair selection.

The feedback budget is:

```text
K = 10 pairwise comparisons
```

The process is:

1. Start with an empty preference history.
2. Select a product pair to ask about.
3. Generate the user's binary preference label.
4. Add the labeled pair to the preference history.
5. Update the posterior belief over the latent preference.
6. Repeat until 10 pairwise comparisons are collected.
7. Rank all candidate products using the final latent belief.

The next pair is selected by minimizing expected posterior entropy. Intuitively, the model tries to choose the pair that is expected to reduce uncertainty about the user's latent preference the most.

## 7. Recommendation and Ranking

After collecting 10 pairwise preferences, the model computes the posterior latent belief:

```text
q(z | C_10)
```

where `C_10` is the preference context after 10 comparisons.

Then it scores all 187 candidate products using:

```text
r(product, z)
```

The product with the highest score is selected as the final recommendation.

## 8. Metrics

The current evaluation uses the following metrics.

### Regret

Regret measures the utility gap between the oracle-best product and the product recommended by the model:

```text
regret = utility(best product) - utility(recommended product)
```

Lower regret is better.

### Normalized Regret

Normalized regret divides regret by the maximum possible regret in that episode:

```text
normalized regret = regret / (best utility - worst utility)
```

Lower normalized regret is better.

### Success@k

Success@k equals 1 if the recommended product is among the user's top-k products by true utility, and 0 otherwise.

For example:

```text
Success@5 = 1
```

means the recommended product is one of the user's top 5 products out of the 187-product candidate pool.

### Threshold Success Rate

Threshold success equals 1 if the recommended product is within the 70th percentile of product utilities for that user.

This is less strict than Success@k because it checks whether the recommendation is good enough, not whether it is exactly among the top few products.

### Average Uncertainty Reduction

VPL tracks uncertainty using the entropy of its Gaussian posterior over the 8-dimensional latent variable.

After each pairwise comparison, the model computes how much the posterior entropy decreases:

```text
uncertainty reduction = entropy before - entropy after
```

The reported value is the average reduction per interaction turn.

Important caveat: this uncertainty value should not be directly compared with uncertainty values from models that use a different belief representation, because the entropy scale depends on the posterior type.

## 9. Current VPL Results

The final VPL baseline uses:

```text
K = 10 sequential active pairwise comparisons
scoring mode = reward_model
candidate products = 187
test users = 125
```

The current VPL active-query results are:

| Metric | VPL |
| --- | ---: |
| Average regret | 0.0164 |
| Average normalized regret | 0.0865 |
| Success@10 | 0.4480 |
| Success@5 | 0.3200 |
| Success@1 | 0.0640 |
| Threshold success rate | 0.8880 |
| Average uncertainty reduction | 0.6079 |

These results show that VPL often recommends products with utility close to the oracle-best product, which explains the low regret. However, exact top-k recovery is harder: the model may recommend a product that is close in utility to the best product but not exactly within the user's top-k products.

## 10. Important Interpretation

VPL is a valid pairwise-preference baseline, but it should be interpreted carefully.

Its main strength is low regret: it can find high-utility products from limited pairwise feedback.

Its main weakness is rank precision: Success@k is lower because pairwise feedback provides sparse information, and many products may have similar utilities.

Uncertainty reduction should be reported separately or explained carefully, because VPL uses Gaussian posterior entropy, which may not be on the same scale as uncertainty metrics from other models.
